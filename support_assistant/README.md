# Module 3 — Support Assistant

## Components

- `docs/` contains the eight exact policy documents required by the assignment.
- `ingest.py` performs one-document-per-chunk ingestion, embeds each chunk with `sentence-transformers/all-MiniLM-L6-v2`, and stores the vectors in a persistent ChromaDB collection using cosine distance.
- `prompt.py` contains the actual role–context–task–format–length prompt, an explicit negative constraint, and a few-shot example. It also contains the prompt used only by the optional `MOCK_LLM=0` intent classifier.
- `main.py` defines the LangGraph `StateGraph`, Pydantic response schema, FastAPI endpoint, required deterministic mock path, and optional real-LLM path with corrective retries.
- `example_calls.py` executes both required example calls and records the actual JSON responses in `example_responses.json` and in this README between the generated markers below.

## Required RAG flow

1. **Ingestion:** `ingest.py` reads `docs/doc_01.txt` through `doc_08.txt` and uses the whole short document as one chunk. It assigns each chunk its document ID (`doc_01` … `doc_08`).
2. **Embedding:** `SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")` converts the eight chunks to local embeddings with no API key.
3. **Storage/retrieval:** ChromaDB stores the vectors in the persistent `zepto_policy` collection. `retrieve_and_answer` embeds the incoming query and retrieves the top three chunks using cosine similarity.
4. **Generation:** in the required default/mock mode, `retrieve_and_answer` returns the deterministic `Based on the retrieved context: ...` template using the top retrieved chunk, while `direct_answer` returns the fixed general-question response. With `MOCK_LLM=0`, the optional real-LLM path uses the structured prompt and Pydantic validation.

## LangGraph routing

The graph contains exactly the required three named nodes:

```text
START
  |
  v
classify_intent
  |
  +---- policy_question ----> retrieve_and_answer ----> END
  |
  +---- general_question ---> direct_answer ----------> END
```

With `MOCK_LLM` unset or set to `1`, `classify_intent` uses the assignment's exact keyword heuristic: `delivery`, `return`, `refund`, `membership`, `tracking`, `cancel`, `gift card`, or `support hours` route to `policy_question`; everything else routes to `general_question`. No LLM call is made in either case. With `MOCK_LLM=0`, only the classification/generation steps switch to the optional real-LLM path; query embedding and Chroma retrieval remain local and active.

## Structured output

The FastAPI response is validated by the `AnswerResponse` Pydantic model:

```text
answer: string
sources: list[string]
confidence: float in [0, 1]
```

In mock mode, `sources` is the retrieved chunk IDs for policy questions and `[]` for general questions; `confidence` is deterministically `1.0`. In the optional real-LLM path, the Pydantic schema rejects extra fields and invalid types/values; an answer is also rejected when it names a source ID outside the retrieved chunks. Invalid structured output is retried up to two additional times before returning a clearly marked error response.

## Run locally — required baseline

From this directory:

```bash
python ingest.py
python example_calls.py
uvicorn main:app --reload --port 7860
```

The required example calls are also the ones generated by `example_calls.py`:

```bash
curl -X POST http://127.0.0.1:7860/ask -H "Content-Type: application/json" -d "{\"query\":\"What is the delivery policy?\"}"
curl -X POST http://127.0.0.1:7860/ask -H "Content-Type: application/json" -d "{\"query\":\"What is the capital of India?\"}"
```

Run the examples with `MOCK_LLM` left unset/default. Do not hand-write the response transcript; `python example_calls.py` writes the actual responses into this README and `example_responses.json`.

## Docker

From the repository root, use the module directory as the Docker build context because the Dockerfile copies `requirements.txt` and `docs` from that context:

```bash
docker build -t zepto-support-assistant ./support_assistant
docker run --rm -p 7860:7860 zepto-support-assistant
```

The image installs the support-assistant requirements, ingests the eight policy chunks during image build, and starts FastAPI on port 7860. The container is the required local baseline; no cloud deployment is required.
